# Goshtoso v0.0.12 Consumer Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Read the
> repository's `using-goshtoso` skill, but treat the tagged v0.0.12 migration
> guide as authoritative when an installed skill example still shows removed
> alpha APIs.

**Goal:** Upgrade every Manja consumer module to exactly
`github.com/araihu/goshtoso v0.0.12`, migrate all removed component APIs and
behavioral assumptions, regenerate consumer-owned outputs, and verify affected
public and management pages rather than stopping at a dependency bump.

**Architecture:** Keep Goshtoso as an external presentation dependency used
only by Manja's self-hosted web layer. Migrate templates to the v0.0.12 public
component model—package-owned `Tone`, `Appearance`, and `Mode` dimensions,
functional-option atomics, concrete component instances, and composition
instead of removed renderer internals. Do not expose Goshtoso through the new
public `domain` or `application` packages.

**Tech Stack:** Go 1.26.5 or newer (v0.0.12's module minimum), templ v0.3.1020,
Goshtoso v0.0.12, server-rendered HTML, HTMX, Alpine.js, Playwright Chromium,
Go unit/E2E tests, and Manja's existing Air development loop.

## Global Constraints

- Run this migration in a fresh dedicated worktree from the then-current
  `origin/main`, after the Open Core extension-surface checkpoint has merged
  and before release-tracks UI/template work begins.
- Preserve unrelated changes and record baseline failures before the bump.
- Update both Go modules: root `github.com/araihu/manja` and
  `github.com/araihu/manja/site`.
- Require exactly `github.com/araihu/goshtoso v0.0.12` in the resolved module
  graph. No pseudo-version, `replace`, or compatibility fork.
- Raise both modules' Go/toolchain requirement consistently because Goshtoso
  v0.0.12 declares Go 1.26.5 or newer.
- Do not recreate removed Goshtoso class assemblers, render fragments, default
  resolvers, or private helpers in Manja merely to compile.
- Edit `.templ` sources and regenerate `*_templ.go`; never hand-edit
  generated templ output.
- Keep the existing embedded Goshtoso asset handler and
  `head.Dependencies()` contract unless a failing v0.0.12 integration test
  proves a tagged API change.
- Preserve read-only public documentation, HTMX navigation, Ctrl/Cmd+K search,
  request-composer behavior, Manja/Goshtoso/Minimal themes, and no upstream
  request proxy.
- Do not push, deploy, release, merge, or remove the worktree without explicit
  authorization.

## Goshtoso Snag Record

This planning inspection required a Goshtoso source dive for two concrete
reasons:

1. the currently installed `using-goshtoso` skill still demonstrates
   `button.Config{Variant: ...}`, which v0.0.12 removes without aliases; and
2. Manja relies on removed renderer-owned class helpers
   `badge.Config.SoftVariantClasses` and `table.BadgeCellClasses`; the tagged
   table source confirms `table.Cell.Component` is the supported composition
   path for rendering `badge.Badge` instead.

The module download also revealed the Go minimum increase from Manja's 1.26.1
to Goshtoso's 1.26.5. These are migration inputs, not reasons to patch Goshtoso
or recreate its internals.

Rename Manja helpers such as `managementPublicationBadgeVariant`,
`methodBadgeVariant`, and `responseBadgeVariant` to `...Tone` so local

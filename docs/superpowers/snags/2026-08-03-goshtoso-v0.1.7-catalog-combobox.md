# Goshtoso v0.1.7 catalog combobox adoption

## Boundary

- Surface: renderer-only OpenAPI catalog header.
- Dependency: released `github.com/araihu/goshtoso@v0.1.7` in the root and
  `site/` consumer modules, with no module replacement.
- Upstream check: v0.1.7 is the latest released tag. The combobox files at the
  release commit match current upstream `main` at the time of adoption.
- Manja owns catalog option projection, mount admission, request bounds, and
  navigation after `combobox:change`. Goshtoso owns combobox markup, keyboard
  behavior, HTMX fragments, selection state, and the change event contract.

## Snags

- `combobox.Source.LazyEndpoint` documents a loading-first behavior, but the
  v0.1.7 component has no initial lazy-load trigger. Only the search field
  issues `hx-get`. Manja uses the public `TriggerAttrs` extension to fetch the
  bounded option list on first open, while first paint contains at most the
  selected option. The Goshtoso options endpoint owns subsequent filtering.
- `combobox.Handler` registers `Config.ID` in a process-global registry and
  panics when another handler with the same ID is constructed. Per-renderer or
  per-test construction is therefore unsafe. Manja constructs one package-wide
  Goshtoso handler and passes each admitted immutable catalog snapshot through
  request context to its provider.
- Both behaviors required an upstream source dive; neither is repaired by
  copying Goshtoso internals. They are candidates for future Goshtoso API/docs
  improvements.
- Goshtoso v0.1.7 `search.Config.ItemsURL` loads one complete static payload on
  first open, filters it in the browser, and hides the result panel while the
  query is empty. It has neither a per-query remote-source contract nor an
  empty-query slot. Embedding all 3,028 Kubernetes records would violate the
  catalog's bounded first-paint goal, while using `/search.json` directly would
  make the server the primary search engine and still would not support recent
  visits. Manja therefore keeps Goshtoso's command-palette interaction and
  semantic-token styling, but owns a catalog-specific Alpine adapter that
  resolves the immutable search directory and only the required posting/record
  shards in the browser. Every child is length- and SHA-256-verified; the live
  server search endpoint is a typed fallback. A future generic Goshtoso API
  could expose remote-query and empty-query slots without learning Manja's
  catalog or history semantics.
- The catalog browser router uses the same versioned shard format and ranking
  rules as `application/catalog`, but JavaScript does not expose Go's exact
  Unicode case-fold implementation. It performs NFKC plus lowercase for the
  primary path; any client error or unsupported edge falls back to the
  canonical server implementation. The existing broader Wasm router design can
  later consume the same immutable child routes without changing public URLs or
  moving management behavior into renderer core.

## Evidence

- Root and `site/` resolve Goshtoso v0.1.7 without replacement.
- Focused template, handler, renderer gateway, and architecture tests pass.
- Focused Chromium regression passes repeatedly and covers first-open loading,
  server filtering, automatic selection navigation, client-side content search
  with `/search.json` blocked, server fallback with search shards blocked,
  recently visited items, and Escape/Ctrl+K without page navigation or reload.
- Pinned Kubernetes receipt remains 65 documents, 1,202 operations, 1,826
  schemas, and 3,028 exact-searchable detail IDs; the client search directory is
  433,346 bytes, total search artifacts are 3,563,134 bytes, maximum document
  HTML is 30,535 bytes, and maximum exact-search fallback JSON is 1,556 bytes.
- Live-browser journey: 65 distinct document keys; server-side filtering from
  65 options to the two `lifecycle` options; selection navigates directly to
  `/documents/lifecycle-v1alpha1/`; Ctrl+K opens `#catalog-search-dialog` in
  place, and Escape closes it without navigation or reload; obsolete Open and
  Search header buttons are absent.

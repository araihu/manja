# Goshtoso v0.1.7 catalog combobox adoption

## Boundary

- Surface: renderer-only OpenAPI catalog header.
- Dependency: released `github.com/araihu/goshtoso@v0.1.7` in the root and
  `site/` consumer modules, with no module replacement.
- Upstream check: v0.1.7 is the latest released tag. The combobox files at the
  release commit match current upstream `main` at the time of adoption.
- Manja owns catalog option projection, mount admission, request bounds, and
  navigation after `combobox:change`. Goshtoso owns combobox markup, keyboard
  behavior, HTMX fragments, selection state, and the change event contract.

## Snags

- `combobox.Source.LazyEndpoint` documents a loading-first behavior, but the
  v0.1.7 component has no initial lazy-load trigger. Only the search field
  issues `hx-get`. Manja uses the public `TriggerAttrs` extension to fetch the
  bounded option list on first open, while first paint contains at most the
  selected option. The Goshtoso options endpoint owns subsequent filtering.
- `combobox.Handler` registers `Config.ID` in a process-global registry and
  panics when another handler with the same ID is constructed. Per-renderer or
  per-test construction is therefore unsafe. Manja constructs one package-wide
  Goshtoso handler and passes each admitted immutable catalog snapshot through
  request context to its provider.
- Both behaviors required an upstream source dive; neither is repaired by
  copying Goshtoso internals. They are candidates for future Goshtoso API/docs
  improvements.

## Evidence

- Root and `site/` resolve Goshtoso v0.1.7 without replacement.
- Focused template, handler, renderer gateway, and architecture tests pass.
- Focused Chromium regression passes repeatedly and covers first-open loading,
  server filtering, automatic selection navigation, and Ctrl+K focus.
- Pinned Kubernetes receipt remains 65 documents, 1,202 operations, 1,826
  schemas, and 3,028 exact-searchable detail IDs; maximum document HTML is
  24,648 bytes after the lazy first-open correction.
- Live-browser journey: 65 distinct document keys; server-side filtering from
  65 options to the two `lifecycle` options; selection navigates directly to
  `/documents/lifecycle-v1alpha1/`; Ctrl+K navigates to `/search` and focuses
  `#catalog-search-query`; obsolete Open and Search header buttons are absent.

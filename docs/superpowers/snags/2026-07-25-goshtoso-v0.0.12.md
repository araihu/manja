## Consumer Skill Example History

The installed `using-goshtoso` skill demonstrated this removed call during the
planning inspection:

```go
button.Button(button.Config{Variant: button.Primary})
```

Goshtoso v0.0.12 removes `button.Config`, the generic `Variant` vocabulary,
and compatibility aliases. The tagged migration guide is authoritative:
Manja must use `button.Button(options ...button.Option)` with package-owned
options such as `button.WithTone(button.TonePrimary)`.

The installed skill was refreshed before implementation and now demonstrates
`button.Button(button.WithTone(button.TonePrimary), ...)`. The planning-time
source dive remains relevant historical friction, but the current skill example
is no longer stale. Its asset, `head.Dependencies()`, templ-generation, and
consumer-boundary guidance remains applicable; the tagged v0.0.12 migration
guide is authoritative for this task.

## Removed Renderer Helpers

Manja currently calls:

- `badge.Config.SoftVariantClasses`
- `table.BadgeCellClasses`

Both are removed/private renderer internals in v0.0.12. Resolving the migration
required reading the tagged migration guide and
`components/table/types.go`/`table.templ`. The supported path is to compose
`badge.Badge` directly and, inside a table, assign it to
`table.Cell.Component`.

Impact: the consumer migration must change table-cell construction and rendered
behavior tests. It must not recreate the removed class assemblers in Manja.

# Goshtoso v0.0.12 Consumer Migration Snags

Date: 2026-07-25
Status: Planning evidence; migration not implemented

## Stale Consumer Skill Example

The installed `using-goshtoso` skill still demonstrates:

```go
button.Button(button.Config{Variant: button.Primary})
```

Goshtoso v0.0.12 removes `button.Config`, the generic `Variant` vocabulary,
and compatibility aliases. The tagged migration guide is authoritative:
Manja must use `button.Button(options ...button.Option)` with package-owned
options such as `button.WithTone(button.TonePrimary)`.

Impact: the skill is useful for assets, `head.Dependencies()`, templ
generation, and consumer boundaries, but its component-call example cannot be
copied during this migration.

## Removed Renderer Helpers

Manja currently calls:

- `badge.Config.SoftVariantClasses`
- `table.BadgeCellClasses`

Both are removed/private renderer internals in v0.0.12. Resolving the migration
required reading the tagged migration guide and
`components/table/types.go`/`table.templ`. The supported path is to compose
`badge.Badge` directly and, inside a table, assign it to
`table.Cell.Component`.

Impact: the consumer migration must change table-cell construction and rendered
behavior tests. It must not recreate the removed class assemblers in Manja.

## Go Toolchain Floor

`go mod download github.com/araihu/goshtoso@v0.0.12` reports that the module
requires Go 1.26.5 or newer. Manja root and `site/` currently declare Go
1.26.1.

Impact: the migration plan raises both modules and any pinned CI/container
toolchain consistently before compiling v0.0.12.

## Missing Intermediate Changelog Entry

Manja currently resolves Goshtoso v0.0.10, while the v0.0.12 migration guide
uses v0.0.11 as its exact base. The tagged v0.0.11 module tree does not contain
a `CHANGELOG.md` entry.

Impact: execution must inspect the official v0.0.10-to-v0.0.11 comparison and
record the absence rather than inventing intermediate release notes.

## Scope Decision

No Goshtoso library change, compatibility fork, copied helper, or dependency
bump is part of this planning checkpoint. The dedicated migration plan isolates
the consumer upgrade after the Open Core checkpoint and before release-track
template work.
